# Expanded prompting evaluation: protocol frozen before generation

I want to investigate whether a more specific supportive prompt improves responses without changing the underlying model. The original eight-case pilot did not establish an improvement. This extension keeps both original prompts unchanged and evaluates 60 new synthetic scenarios. It is a held-out extension of an exploratory study, not a preregistered confirmatory trial.

The coding agent authored and reviewed ten scenarios in each of six categories: learning, work, relationships, everyday constraints, uncertainty, and positive events or explicit preferences. The contexts vary in practical constraints, requests to listen rather than advise, uncertainty, positive emotions and competing priorities. No real conversations or identifying details are included. The authoring agent also knows the prompts; independent authorship and representative sampling are not claimed. All cases are single-turn ordinary adult contexts. Broader safety and multi-turn routing are evaluated separately.

Qwen2.5-1.5B-Instruct remains pinned to `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`. The original A/B prompts, greedy decoding, 110-token limit, seed 42, CPU float32 and eight Torch threads remain fixed. Each input is paired across both conditions, with deterministic randomised order. The input plus output budget must fit 2,048 tokens; inputs are rejected rather than silently truncated. One separate warm-up is recorded and excluded from paired analysis. Warm-up and added timing instrumentation differ from the original pilot, so latency comparisons across studies are not causal estimates.

`check_expanded_integrity.py` verifies unique conversation groups, exact-text separation from development and pilot test data, and separation from the four original few-shot examples. Token-set Jaccard similarity of at least 0.65 flags candidates for inspection; it cannot exclude semantic duplication or pretraining contamination. The original archive is not opened by this experiment. Hashes bind the new inputs, original prompt configuration, protocol, rubric and runner before generation.

The primary quality outcome remains relevance. Emotional acknowledgement, grounding, clarity, practical helpfulness and autonomy are separate ordinal 1–5 outcomes. Safety hazards remain separate binary annotations. Two independent reviewers are unavailable, as confirmed by Bushra; no human scores, agreement statistics or quality confidence intervals will be invented. Existing pilot packets remain available, and new blank packets can be generated from completed outputs. Raw execution diagnostics such as token counts are not empathy measures.

When ratings become available, preserve original sheets and analyse each reviewer separately before any agreed aggregation. Use paired B−A differences within scenarios, bootstrap whole scenario pairs with 10,000 resamples and seed 42, and report per-category counts and missingness. For ordinal agreement, report weighted Cohen's kappa on jointly rated items with the weighting scheme specified; do not compute it on blank sheets. Intervals that cross zero establish neither superiority nor equivalence. Category results are exploratory and secondary dimensions require caution about multiple comparisons.

`controlled_inference.py` records outputs, failures, UTC boundaries, loading time, token counts, time to first token, decode throughput and boundary process RSS. RSS is not isolated model memory or measured peak memory. TTFT includes framework overhead; no pure prefill throughput is claimed. Failed and interrupted runs retain their manifests and completed rows. No training or browser inference is performed.

The related performance investigation will repeat the original caregiving outlier input five times per condition in a fresh process after a recorded warm-up. It will retain every observation and report p50/p95 as descriptive small-sample quantiles. It cannot retrospectively identify an operating-system interruption that was not logged during the original pilot.

Milestone 3 remains partially complete without independent ratings. Public release still requires browser verification, broader safety review and the user's approval. LoRA training remains disabled pending baseline approval.
