# Milestone 4 proposal: controlled LoRA adaptation

This is a preparation document, not approval to train. Milestone 3 remains partially complete because independent ratings are unavailable and broader safety/browser evidence is missing. `configs/milestone_4.pilot.json` explicitly disables training. It is a proposal schema, not an argument file for the existing training script. When this protocol was first written, no adapter had been instantiated or trained. Since then a 4-step CPU smoke run (`results/lora/smoke-v1`) has trained and saved a throwaway adapter to check the pipeline. It says nothing about quality. No pilot has been run.

On 21 November 2026, after an external review, `scripts/lora_pilot.py` was changed so that a pilot's accounting is correct: validation loss is weighted by the tokens the shifted loss actually averages over; a final partial accumulation group is applied rather than dropped; adapter folders are named from the whole output path, and an existing one is never overwritten; the validation partition hash is checked as well as the training one; and truncated replies are recorded by id (or dropped with `--drop-truncated`). The smoke run predates these changes, so its manifest's `runner_sha256` no longer matches the script. The tested library versions are pinned in `requirements-lora-tested.txt`.

The primary comparison is B versus C: the same pinned Qwen2.5-1.5B-Instruct base, the same tokenizer and optimised prompt, with only C receiving the adapter. Keep generation settings and final test inputs unchanged. A different model size or quantisation format would introduce another treatment and belongs in a separate experiment.

The candidate training source is the audited official-source EmpatheticDialogues training partition, under its documented CC BY-NC 4.0 restrictions. The quarantined archive is excluded even where its strings resemble the official source. Before training, select complete conversation groups with a seeded procedure, freeze source IDs and hashes, and confirm separation from development, validation, few-shot and final test groups. Start with no more than 256 training rows without splitting groups. Freeze a small validation subset from the independent validation partition before comparing learning rates. Do not use final-test response quality to select examples, ranks or checkpoints. Review licence obligations before any adapter or dataset publication.

The proposed first pilot uses rank 8, alpha 16, dropout 0.05 and q_proj/v_proj modules, one epoch, batch size one and gradient accumulation eight. Compare learning rates 1e-4 and 2e-4 using validation loss and a separate development safety review. Train on assistant tokens only, mask padding, verify chat-template alignment and reject examples whose assistant response is completely truncated. These are starting hypotheses, not tuned values or guaranteed improvements.

Read-only inspection of the local pinned safetensors header found 56 q_proj/v_proj weight tensors across 28 layers. Rank 8 would add approximately 1,089,536 parameters for these shapes, excluding any other trainable components. This is a shape-derived estimate, not a measured training footprint. The inspection record is `results/completion_2026_11_07/lora_target_inspection.json`.

The current measured environment supports CPU float32 inference. No feasible training throughput or GPU memory budget has been measured. Choose a dedicated compatible GPU, verify available memory and supported dtype, and obtain approval before a memory smoke test. Ordinary LoRA is the proposed first intervention; defer QLoRA until quantised training support and its additional numerical/runtime variables are justified. Do not silently switch hardware or quantisation between B and C evaluation.

Record model/tokenizer revisions, package versions, hardware, dataset selection and hashes, full hyperparameters, seed, setup/training time, token counts, peak allocated GPU memory where supported, adapter bytes and all failures. Keep process RSS separate from allocated device memory. Record cold/warm loading and inference using the established instrumentation, controlling host sleep and noting cache state. Preserve unsuccessful trials rather than reporting only the selected checkpoint.

Evaluate the unchanged final 60-case set with independent blinded quality review, separate hazard ratings and the frozen routing regression suite. Report paired B−C comparisons with uncertainty and per-category outcomes. New safety cases for a successor detector must be independently frozen: the inspected S1 held-out failures are no longer unseen development evidence for that successor. An apparent quality gain cannot offset an unexamined safety deterioration.

Before launch, the user must approve the baseline evidence, data selection, annotation plan, compute allocation and this protocol. Resolve the current missing independent ratings or explicitly agree a narrower exploratory objective; do not relabel such an exception as validated quality. Browser release remains blocked independently of whether local research training is later approved.

Future systems experiments may compare model size, quantisation, runtime and device class one factor at a time. Selective routing comes after fixed-model baselines and must include model-loading/switching cost. None of those comparisons has results yet.
